## Why

Briefs F1 (calendar sync adds meetings by itself), F2 (copy a meeting as minutes) and F8 (copy the Actions list) each
need a stored value or a helper that touches all three backends or the same component. Building those once, first,
lets the three run side by side without touching the same files.

## What to build

1. **Setting `calendarAutoAdd: boolean`, default `true`.** Rust name `calendar_auto_add`. A config file without the
   key loads as `true`. Store `calendarAutoAdd` in `src/lib/stores.ts` next to `calendarSyncEnabled`; setter
   `setCalendarAutoAdd(enabled)` in `tauriApi.ts`; filled in `boot.ts` next to line 594.
   Settings row directly under the calendar toggle, shown only while `$calendarSyncEnabled` is on:

   | Language | Label | Description |
   | :--- | :--- | :--- |
   | English | Add new meetings automatically | New meetings appear in the note by themselves. Changes that move or remove what you wrote still ask first. |
   | Dutch | Nieuwe afspraken automatisch toevoegen | Nieuwe afspraken komen vanzelf in de notitie. Wijzigingen die jouw tekst verplaatsen of verwijderen vragen het eerst. |

2. **Setting `minutesName: string`, default `""`.** Rust `minutes_name`, trimmed, at most 60 characters (longer is cut
   on save). Store `minutesName`; setter `setMinutesName(name)`. Settings row in Notes & Sync, under the Startup row:
   a text input, 220 px wide, saved 400 ms after the last keystroke and when it loses focus.

   | Language | Label | Description |
   | :--- | :--- | :--- |
   | English | Your name in minutes | Shown as the owner of your own actions when you copy a meeting as minutes. Empty: no owner. |
   | Dutch | Je naam in notulen | Staat als eigenaar bij je eigen acties als je een overleg als notulen kopieert. Leeg: geen eigenaar. |

3. **Session field `autoAddedMeetings: Record<string, string[]>`** (date `YYYY-MM-DD` to meeting titles), optional,
   absent in old files and then read as `{}`. Rust: `auto_added_meetings: Option<BTreeMap<String, Vec<String>>>`
   with `#[serde(default, skip_serializing_if = "Option::is_none")]`. `write_tab_session` gets a fourth argument
   `autoAddedMeetings` in every backend. On write, every backend drops dates before today's date (the frontend passes
   today as it already does for `lastOpenedDate`; use that value). Store `autoAddedMeetings` in `stores.ts`, filled
   where the session is read (`boot.ts` lines 399 and 630), passed at line 545. Add
   `export function recordAutoAddedMeetings(date: string, titles: string[]): void` in a new file
   `src/lib/autoAddedMeetings.ts`: merges the titles into the store for that date (no duplicates, compared after
   `trim().toLowerCase()`) and writes the session at once through the same code path line 545 uses (extract that
   call into a function both use; do not duplicate it).
   Add two cases to `storage-cases.json`: the field round-trips; a date before today is dropped on write.

4. **`src/lib/clipboardWrite.ts`:** `export async function copyRich(html: string, plain: string): Promise<boolean>`.
   Tries `navigator.clipboard.write([new ClipboardItem({ "text/html": new Blob([html], { type: "text/html" }),
   "text/plain": new Blob([plain], { type: "text/plain" }) })])`; if that throws or `ClipboardItem` is missing,
   `navigator.clipboard.writeText(plain)`; if that throws, the textarea fallback from
   `EditorContextMenu.svelte`. Returns false only when all three failed. Also export
   `copyPlain(text: string): Promise<boolean>`, which is the last two steps only, and make the Copy as Markdown item
   in `EditorContextMenu.svelte` call `copyPlain` instead of its own inline fallback.

All new text keys go into all seven languages with one script; mark the five not given above as "needs a native
